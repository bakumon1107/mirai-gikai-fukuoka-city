# 福岡市版 委員会議事録 トピック分割表示 設計書

## 1. 背景・目的

福岡県版みらい議会の委員会ページでは、各会議が「議題（トピック）」ごとに整理され、
- **会議詳細ページ**: 「この日に話し合われた議題」として番号付きの箇条書きリスト（議題タイトル＋要約＋該当やり取りへのリンク）
- **議事録（transcript）ページ**: 議題ごとにセクション分割され、見出し（`番号. タイトル`）＋`#topic-N` アンカーで各議題に直接ジャンプ可能

という形で、市民が「その日に何が話し合われたか」を一覧で把握できる。

参照（県版・本番）:
- 一覧: https://mirai-gikai-fukuoka-pref-web.vercel.app/committees
- 会議詳細: https://mirai-gikai-fukuoka-pref-web.vercel.app/committees/kuko-kotsu-infra/6618
- 議事録: https://mirai-gikai-fukuoka-pref-web.vercel.app/committees/kuko-kotsu-infra/6618/transcript#topic-5

福岡市版でも同様に、**会議詳細でトピックを箇条書き表示**し、かつ**議事録内の議論をトピック分割**する。

## 2. 現状分析（市版 `mirai-gikai-committee-city`）

トピック分割の**インフラは約9割が既に実装済み**。不足しているのは「トピックデータ」と「会議詳細の議題箇条書き描画」のみ。

### 2.1 実装済み（変更不要）
| 層 | ファイル | 状態 |
|---|---|---|
| DBテーブル | `committee_meeting_topics`（`topic_order` / `title` / `summary` / `discussion_summary` / `start_voice_no` / `end_voice_no`） | 作成済み・**0件（未生成）** |
| 型 | `shared/types.ts` の `CommitteeMeetingTopic`・`CommitteeMeeting{Summary,Detail}.topics` | 完備 |
| リポジトリ | `server/repositories/committee-meeting-repository.ts` | 3クエリすべて `committee_meeting_topics (*)` を取得しマッピング済み |
| transcript分割 | `shared/utils/build-transcript-sections.ts` | `startVoiceNo`〜`endVoiceNo`（**seq を格納**）で発言をセクション分割。topics空なら全体1セクション |
| transcript描画 | `client/components/chat-transcript.tsx` | 議題見出し `{topicOrder}. {title}` ＋ `id="topic-N"` アンカー＋`scroll-mt-24` 実装済み |

> 重要: `build-transcript-sections.ts` のコメント通り、`start_voice_no` / `end_voice_no` カラムには **`voiceNo` ではなく `seq`（会議全体の発言連番）を格納する**運用。

### 2.2 不足（今回実装）
1. **トピックデータが空** … `committee_meeting_topics` 0件。生成が必要。
2. **会議詳細に議題リストが無い** … `server/components/meeting-detail-view.tsx` は会議要約とtranscriptリンクのみで、県版の「この日に話し合われた議題」箇条書きが未実装。
3. **AIパッチにtopicsが無い** … `docs/data/committee-minutes/2026/ai/<DocumentID>.json` は現在 `{ documentId, meetingSummary, speechSimpleTexts }` のみ。
4. **applyスクリプトがtopicsを反映しない** … `packages/seed/fukuoka/apply-committee-ai-content.ts` は `summary` と `speeches[].simpleText` のみ更新。

### 2.3 県版との構造差（重要）
- 県版: 議事録に**明示的な議題（○○について）マーカー**があり、**パーサが議題境界を抽出**して seed 時に topics を生成。AIパッチは `topicSummaries`（`topic_order` ごとの要約）だけ追加。
- 市版: 予算分科会等は**匿名の質疑応答が連続**し、議題マーカーが無い。したがって**トピックの境界（seq範囲）自体をAIで判定**する必要がある（パーサ自動抽出は不可）。

## 3. 設計方針

### 3.1 トピック生成方式（決定）
市版はパーサではなく **AIパッチにトピックを追記**する方式を採る。既存の `ai/<DocumentID>.json` に `topics` 配列を追加する（`speechSimpleTexts` はそのまま保持）。

拡張後のパッチスキーマ:
```jsonc
{
  "documentId": 3503,
  "meetingSummary": "…（会議全体の要約・既存）…",
  "topics": [
    {
      "topicOrder": 1,
      "title": "志賀島の集客促進と観光振興",
      "summary": "市営渡船を使った志賀島のイベント実績や、宿泊事業者と連携した通年誘客の考え方が議論されました。",
      "startSeq": 1,   // 該当範囲の最初のseq（非noteの開始）
      "endSeq": 15     // 該当範囲の最後のseq（inclusive）
    }
    // …
  ],
  "speechSimpleTexts": [ { "seq": 1, "simpleText": "…" }, … ]  // 既存・変更なし
}
```

- `startSeq` / `endSeq` は **seq（`CommitteeSpeech.seq`）** を指す。DBの `start_voice_no` / `end_voice_no` にそのまま格納する。
- 粒度: 1文書あたりおおむね **5〜15トピック**。質問者の交代・所管事項（局・事業）の切れ目でまとめる。既存の `meetingSummary` に列挙した論点がほぼトピックに対応する。

### 3.2 被覆ルール（検証で機械チェック）
- すべての**非note**セグメントは、いずれか1つのトピック範囲に**重複なく**属する。
- トピックは `topicOrder` 昇順で `startSeq` も昇順、`startSeq <= endSeq`、範囲は連続（トピック間にすき間を作らない。冒頭の開会・調査事項などの note は最初のトピック開始 `startSeq` より前に置き、transcript 上は `topic=null` の opening セクションに落ちる）。
- `title` は空でない。`summary` は1〜2文（会議詳細の箇条書きに出る説明文）。

### 3.3 discussion_summary の扱い（決定）
今回は**未使用**（`summary` のみ使用、県版と同じ）。将来「議題ごとの詳細要約」を出す場合に備えてカラム・型は温存。

### 3.4 話者（speakers）チップの扱い（決定: 件数バッジ）
県版は課長名など**実名**のチップを議題ごとに表示するが、市版は**匿名**（委員/執行部のみ）。
→ **各議題に「質疑・意見 n件／答弁 n件」の件数バッジを出す**。バッジは AI 生成ではなく、
トピックの seq 範囲に含まれる `member` / `executive` セグメント数を**サーバー側で機械集計**して表示する
（`note` は除外）。集計は `meeting-detail-view.tsx` 内の純粋関数に切り出し、テストを付す。

### 3.5 議事録（transcript）の目次（決定: 追加する）
議事録ページ先頭に議題の**目次（TOC）**を追加し、各トピックへ `#topic-N` でジャンプできるようにする。
`chat-transcript.tsx`（Client Component）に、`sections` のうち `topic` を持つものを列挙する目次を実装。
トピックが無い会議（1セクション）では目次を表示しない。

### 3.5 UI実装
1. **`meeting-detail-view.tsx`**（サーバーコンポーネント）に県版同等の議題ブロックを追加:
   - `meeting.topics.length === 0` のとき: 「委員長の選出など手続きが行われました。詳細は発言のやり取りをご覧ください」旨の案内（県版文言を市向けに調整）。
   - `> 0` のとき: `<ol>` で `番号（topicOrder）＋タイトル＋要約＋「このやり取りを読む」→ ${transcriptPath}#topic-${topicOrder}` を表示。
   - 既存トークン（`border-primary` / `bg-mirai-gradient-start` 等）を使用。インラインカラー禁止・`Button`/`lucide-react` ルール遵守。
2. **`chat-transcript.tsx`**: （案A採用時）先頭に目次を追加。それ以外は既存のまま。

## 4. データ生成（トピック付与）

対象文書ごとに、既に読み込んだ議事録本文（`docs/data/committee-minutes/2026/*_<doc>.json` の `speeches`）と、生成済みの `meetingSummary` を根拠に、トピック配列を作る。

- 生成物は **AIコンテンツ**のため、CLAUDE.md「AI生成コンテンツのDB更新ルール」に従い、**DB反映前にユーザー確認**を得る（サンプル提示）。
- 自己レビュー観点: タイトルの日本語自然さ、要約とソースの整合、簡体字混入なし、seq範囲の妥当性（質問者交代と一致）。

### スコープ（決定: R8 全36文書）
R8 **全36文書**（常任委・特別委・予算分科会すべて）にトピックを付与する。
- 予算分科会 28文書: simpleText・summary 生成済み。トピックを追記。
- 常任委・特別委等 8文書: 現状 simpleText 未生成。**本作業で議事録本文を読み、トピック（境界・タイトル・要約）を生成**する。
  会議全体要約（meetingSummary）も未生成の文書はこの機会に併せて生成する。
  ※これら8文書の「わかりやすい表現（simpleText）」生成は本作業のスコープ外（別途）。トピック＋原文で表示される。

## 5. スクリプト改修

`packages/seed/fukuoka/apply-committee-ai-content.ts` に topics 反映を追加（冪等）:
1. パッチ型に `topics?: { topicOrder, title, summary, startSeq, endSeq }[]` を追加。
2. `meeting.id` 特定後、`committee_meeting_topics` の当該 `meeting_id` を**全削除 → insert**（`topic_order` 昇順）。
   - `start_voice_no = startSeq` / `end_voice_no = endSeq` / `summary = summary` / `discussion_summary = null` を格納。
3. `topics` を持たないパッチ（未生成文書）はスキップし、既存の summary/speeches 更新のみ行う（後方互換）。

## 6. 実装ステップ

1. `apply-committee-ai-content.ts` に topics upsert を追加（＋型拡張）。
2. `meeting-detail-view.tsx` に議題箇条書きブロックを追加（県版から移植・市向け調整）。
3. （案A採用時）`chat-transcript.tsx` に目次を追加。
4. トピック検証スクリプト（seq被覆・重複・範囲外・空タイトル）を作成。
5. 対象文書のトピック生成 → 検証 → **ユーザー確認** → ローカルDBへ apply。
6. `pnpm lint` / `pnpm typecheck` / `pnpm test`（純粋関数 `build-transcript-sections` の既存テストにトピック分割ケースを追加）。
7. ローカル `/committees/<slug>/<doc>` と `/transcript#topic-N` を目視確認。
8. コミット（AI JSON＋コード）→ push → PR（base `fukuoka-city/develop`）。CodeRabbitレビュー。

## 7. 検証（受け入れ基準）

1. `pnpm lint && pnpm typecheck && pnpm test` が緑。
2. 対象各文書で、全非noteセグメントがいずれかのトピックに重複なく属する（検証スクリプトOK）。
3. 会議詳細に「この日に話し合われた議題」が番号付き箇条書きで表示され、「このやり取りを読む」で該当 `#topic-N` に遷移する。
4. 議事録がトピックごとにセクション分割され、見出し `番号. タイトル` とアンカーが機能する。
5. トピック未生成の文書は従来どおり（1セクション・詳細は要約のみ）崩れず表示される。

## 8. リスク・注意
- **seq範囲の品質**: トピック境界がずれると無関係な発言が混ざる。検証スクリプトで機械チェック＋サンプル目視。
- **AI生成物のDB反映は要ユーザー確認**（CLAUDE.mdルール）。本番反映はPRマージ後に別途。
- **loader戻り値のシェイプ**: topics は既に型・取得実装済みのため追加改修は不要（`unstable_cache` 不使用のためキャッシュキー影響なし）。
- **スタイル規約**: インラインカラー禁止・`Button`/`lucide-react`・ケバブケース等を遵守。

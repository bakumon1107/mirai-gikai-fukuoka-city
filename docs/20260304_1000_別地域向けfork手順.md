# 別地域向け Fork 手順書

> このガイドは、地方議会版ベーステンプレート（`base-local/develop`）を
> 特定の地方議会向けに fork する際の手順をまとめたものです。
> 川崎市議会版（2026-02）・神奈川県議会版（2026-03）・福岡市議会版の経験を反映しています。

---

## 0-0. その前に：その自治体で何が作れるか調べる

地方議会のサイトは自治体ごとに公開範囲も形式もまったく違います。
議案が件名しか公開されていない、議決結果が非公開、会議録が要旨だけ、といった差があり、
**fork しても主要機能が成立しない自治体があります。**

### 0-0-1. 呼び出し方

**この調査は、ユーザーへの確認や計画の提示より先に実行します。**

```
/council-survey <自治体名>
```

スキル一覧に `council-survey` が出ない場合（fork 元以外のリポジトリで作業しているとき等）は、
下記の SKILL.md を読み、**手順をそのまま実行してください。**
参照して自前の進め方を組み立てるのではなく、Step 1 から順に辿ります。

[.claude/skills/council-survey/SKILL.md](../.claude/skills/council-survey/SKILL.md)

このテンプレート以外のリポジトリで作業している場合は、
base-local の worktree またはクローンを探して同じパスを開きます。

```bash
# 手元のどこかにある base-local のチェックアウトを探す
find ~ -maxdepth 4 -path "*/.claude/skills/council-survey/SKILL.md" 2>/dev/null
```

判定軸・Tier の定義・レポートテンプレートはすべて SKILL.md 側にあります。
**この手順書に書いてある Tier の要約は読み物であって、判定に使うものではありません。**

| Tier | 作れるもの |
|---|---|
| Tier 0 | 財政の可視化、議員名簿（**どの自治体でも作れる**） |
| Tier 1 | 議案一覧 |
| Tier 2 | 議案のAI解説 |

Tier とは別に、賛否の粒度（議員別/会派別/票数のみ/可否のみ/非公開）と
アーカイブの強さ（一般質問・委員会記録・記者会見）を評価します。詳細は SKILL.md。

## 0. 最初に読むもの：FORK_GUIDELINES

本リポジトリは AGPL-3.0 で公開されており、誰でも fork・改変・再配布できます。
ただし本家（team-mirai/mirai-gikai）は、商標保護と利用者の混乱防止のため
[FORK_GUIDELINES.md](../FORK_GUIDELINES.md) で**必須要件**を定めています。
これは AGPL-3.0 第7条 (c)(d)(e) に基づく追加条件であり、遵守は任意ではありません。

| FORK_GUIDELINES の必須要件 | 本テンプレートでの対応状況 |
|---|---|
| 1. サービス名称を「みらい議会＠地域名」形式に | `siteConfig.siteName` を変更する（セクション1-1） |
| 2. ロゴを独自のものに差し替え | プレースホルダー同梱。**必ず差し替える**（セクション5） |
| 3. トップ画像・OGP画像を差し替え | プレースホルダー同梱。**必ず差し替える**（セクション5） |
| 4. カラーテーマを変更 | プレースホルダー配色。**必ず変更する**（セクション1-4） |
| 5. 免責文言の表示 | `showTeamMiraiSection: false` のとき自動表示（対応済み） |
| 6. ソースコード公開先リンクの表示 | `siteConfig.sourceCodeUrl` を**必ず設定する**（セクション1-1） |

> [!WARNING]
> 本テンプレートに同梱されているロゴ・アイコン・OGP画像・配色は、本家の素材を使わないための
> **ニュートラルなプレースホルダー**です。そのまま公開すると、見た目が他の fork 版と区別できず、
> FORK_GUIDELINES の趣旨（利用者の混乱防止）を満たしません。必ず独自のものに差し替えてください。

### 0-1. AGPL-3.0 第13条（ソースコード公開）について

ネットワーク経由でサービスを提供する場合、利用者が**実際に稼働しているバージョン**の
ソースコードを入手できる手段を提供する必要があります。

- `web/src/config/site.config.ts` の `sourceCodeUrl` に、**自分の公開リポジトリ URL** を設定する
- 本家（https://github.com/team-mirai/mirai-gikai ）の URL では代用できない
- リポジトリは誰でもアクセスできる状態にする
- 設定するとフッターに「ソースコード（GitHub）」リンクが表示される。
  **空文字列のままだとリンクが出ず、ライセンス違反の状態になる**

### 0-2. 過去に指摘された典型的な不備

地方版の調査（[山田ゆうじ氏の記事](https://note.com/yujiyamada0512/n/n3d2eea5506fc)）では、
以下が複数の fork 版で問題として挙げられました。本テンプレートでは対処済みですが、
改変の際に再混入させないよう注意してください。

- 同意画面に「回答データは党内での政策検討に利用します」が残っている
- プライバシーポリシーに「政治資金規正法等に基づき7年間保管」「広告配信」が残っている
- 誤り報告ボタンが本家の Google フォームに飛ぶ
- 党への寄附リンクが残っている
- ソースコードへのリンクが本家を指している、または無い
- AIチャットが特定政党の紹介を行う

また、運営者が現職議員・会派・後援会名義である場合の**利益相反の開示**が求められています。
`siteConfig.operator.disclosure` に立場を記載すると、フッターの免責文言の下に表示されます。

## 1. 設定ファイルの変更

### 1-1. `web/src/config/site.config.ts` ← **最重要**

地域固有の情報はこのファイルに集約されています。`★` が付いた項目は必ず変更してください。

```typescript
export const siteConfig = {
  siteName: "みらい議会＠XX市",              // ★ 「みらい議会＠地域名」形式
  siteDescription: "XX市議会で今どんな議案が...",
  cityName: "XX市",                           // 自治体名（県の場合は "XX県"）
  councilName: "XX市議会",                    // 議会名（県の場合は "XX県議会"）
  residentTerm: "市民",                       // 住民の呼称（県民・区民・町民 等）
  keywords: ["みらい議会＠XX市", "議案", ...],
  councilBaseUrl: "https://www.city.xx.lg.jp/",
  councilBillsDetailUrl: "https://www.city.xx.lg.jp/...",  // 議案・議決結果一覧
  twitterHashtag: "みらい議会XX市",           // X のハッシュタグ（# なし）
  sourceCodeUrl: "https://github.com/YOU/YOUR_REPO",  // ★ 自分の公開リポジトリ
  externalLinks: {
    report: "https://forms.gle/...",          // ★ 自前の誤り報告フォーム（空なら非表示）
    aboutNote: "",                            // サービス説明記事（空なら非表示）
    donation: "...",                          // showTeamMiraiSection=true のときのみ使用
    teamAbout: "...",                         // 同上
    terms: "...",                             // 同上
    privacy: "...",                           // 同上
    faq: "",                                  // ★ 空なら /faq ページを使用
  },
  managingParty: "",                          // 政党が運営主体でなければ空のまま
  operator: {
    name: "運営者名",                         // ★
    contactUrl: "https://...",                // ★ 問い合わせ先
    jurisdiction: "XX地方裁判所",             // ★ 利用規約の管轄裁判所
    disclosure: "",                           // 運営者の立場・利益相反の開示文
  },
  features: {
    aiChat: true,                             // AIチャット機能
    aiInterview: false,                       // AIインタビュー機能（既定は無効）
    showTeamMiraiSection: false,              // 党公式として運営する場合のみ true
  },
} as const;
```

#### `managingParty` と `showTeamMiraiSection` の効き方

この 2 つは「党の公式サービスかどうか」を切り替えるスイッチです。非公式運営（既定）では
以下が自動的に適用されます。

| 設定 | `false` / 空（非公式運営・既定） | `true` / 党名あり（党公式） |
|---|---|---|
| `showTeamMiraiSection` | フッターに免責文言を表示。党ロゴ・寄附リンク・党紹介セクションを非表示 | 党ロゴ・寄附リンク・党紹介セクションを表示 |
| `showTeamMiraiSection` | AIチャットのプロンプトに政党紹介を差し込まない | プロンプトに党概要・活動方針を差し込む |
| `managingParty` | 同意文言を「政策検討に活用します」等の汎用表現に | 「◯◯の政策検討に活用します」と党名入りに |
| `managingParty` | プライバシーポリシーから政治資金規正法・政策立案の記述を除外 | 政党向けの記述を表示 |

## 4. 自地域のブランチへ切り替える

テンプレートは `base-local/develop` を基準ブランチとして動いています。
fork したら**自地域のブランチを作り、基準をそちらへ移す**必要があります。
この作業を飛ばすと、CI が動かない・PR のベースがずれる・エージェントが
誤ったブランチを基点にする、といった不具合が出ます。

### 4-1. ブランチを作る

命名は `<地域>/develop` に揃えます（例: `shibuya/develop`、`komoro/develop`）。

```bash
git fetch origin
git checkout -b <地域>/develop origin/base-local/develop
git push -u origin <地域>/develop
```

### 4-2. GitHub のデフォルトブランチを変更する

```bash
gh repo edit --default-branch <地域>/develop
```

Web UI なら Settings → General → Default branch から変更します。
デフォルトブランチを変えておかないと、clone した人が
テンプレートのまま作業を始めてしまいます。

### 4-3. ブランチ名の参照を一括で置き換える

`base-local/develop` を参照している箇所がリポジトリ内に散らばっています。
**まず現状を確認してから置き換えてください。**

```bash
# 置き換え対象の洗い出し
grep -rn "base-local/develop" --include="*.yml" --include="*.md" . | grep -v node_modules

# worktree パスの洗い出し
grep -rn "mirai-gikai-local-worktree" --include="*.md" . | grep -v node_modules
```

対象は以下です（テンプレート作成時点）。

| ファイル | 内容 |
|---|---|
| `.github/workflows/code_check.yml` | `branches:` × 2（push / pull_request） |
| `.github/workflows/integration_test.yml` | `branches:` × 2 |
| `.github/workflows/deploy_web.yml` | コメント内の例。**有効化する場合は 4-5 を参照** |
| `AGENTS.md` | ベースブランチの指定、worktree パス（`CLAUDE.md` はこのファイルへのシンボリックリンク） |
| `.claude/agents/worktree-worker.md` | ブランチ作成の基点、PR のベース |
| `.claude/skills/parallel-pr/SKILL.md` | 同上、worktree パス |
| `.claude/commands/codify.md` | worktree パス |

worktree パス `../mirai-gikai-local-worktree/` も `../mirai-gikai-<地域>-worktree/` 等に
変更しておくと、複数の地域版を同じマシンで扱うときに混ざりません。

置き換え後、取りこぼしがないか再確認します。

```bash
grep -rn "base-local" --include="*.yml" --include="*.md" . | grep -v node_modules
```

### 4-4. ブランチ保護を設定する（任意）

デフォルトブランチへの直接 push を禁止し、PR 経由に統一する場合は
Settings → Branches でルールを追加します。

### 4-5. デプロイを有効化する

テンプレートでは `deploy_web.yml` の push トリガーを無効化してあります。
デプロイする場合は、ワークフロー冒頭のコメントに従って以下を有効にします。

1. `on.push.branches` のコメントアウトを解除し、`<地域>/develop` を指定
2. checkout の `ref:` を同じブランチ名に指定
3. `SUPABASE_*` と `WEB_VERCEL_DEPLOY_HOOK_URL` のシークレットを登録

詳細は [本番環境方針検討](20260219_1100_本番環境方針検討.md) を参照してください。

### 4-6. `base-local/develop` の扱い

**削除せずに残しておくことを推奨します。** テンプレート側の改善を
あとから取り込めるようにするためです。

テンプレートが別リポジトリにある場合は、リモートとして登録しておきます。

```bash
git remote add template <テンプレートのリポジトリURL>
git fetch template
```

取り込み方は2通りです。

| 方法 | 向いている場面 |
|---|---|
| `git merge template/base-local/develop` | テンプレートの変更をまとめて取り込む。地域固有の変更と競合しやすい |
| `git cherry-pick <コミット>` | 必要な修正だけ選んで取り込む。**地域版では通常こちらが現実的** |

地域版は `site.config.ts`・画像・シードデータを大きく書き換えているため、
merge すると毎回その部分が競合します。cherry-pick で必要なものだけ拾うほうが楽です。

## 8. Langfuse プロンプト設定

AIチャット・インタビュー機能では Langfuse でプロンプトを管理しています。
Langfuse 側にプロンプトが登録されていない場合は、`web/src/lib/prompt/source-code/templates/`
のコード内プロンプトがフォールバックとして使われます。

| プロンプト名 | 用途 |
|---|---|
| `top-chat-system` | トップページAIチャット |
| `bill-chat-system-normal` | 議案詳細チャット（通常難易度） |
| `bill-chat-system-easy` | 議案詳細チャット（やさしい） |
| `bill-chat-system-hard` | 議案詳細チャット（詳しい） |

> [!IMPORTANT]
> Langfuse 側でプロンプトを上書きする場合、コード側に入っている中立性のルール
> （特定の政党・会派・候補者を推奨しない、投票を呼びかけない）が失われないよう注意してください。

## 9. クロスプラットフォーム対応（Windows / Mac）

### 10-1. devスクリプトのポート指定

`web/package.json` と `admin/package.json` の dev スクリプトは、Bash の `${VAR:-default}` 構文ではなく
Node.js の `process.env` 経由でポートを読み取る方式です。Windows でも動作するため変更不要です。

### 10-2. Claude CLI（AI情報収集機能）の Windows 対応

`admin/src/features/ai-collection/server/utils/execute-claude.ts` に Windows 対応が組み込まれています。
`CLAUDE_CLI_PATH` 環境変数にフルパスを設定するか、`npm install -g @anthropic-ai/claude-code` を行ってください。

### 10-3. Supabase CLI

`npx supabase start` は Docker を使用します。Windows の場合は WSL2 + Docker Desktop が必要です。

### 10-4. 改行コード

Biome が LF を強制するため、Windows では `git config core.autocrlf input` を推奨します。

川崎版の知見をベースに、福岡市版として新規プロジェクトを作成する。

## Step 1: Supabase プロジェクト作成

### 1-1. プロジェクト作成

1. https://supabase.com にログイン
2. 「New Project」を作成
   - Name: `mirai-gikai-fukuoka-city`
   - Region: **Northeast Asia (Tokyo)** を選択
   - Database Password: 強力なパスワードを設定・保存
3. プロジェクト作成完了まで待つ（約1〜2分）

### 1-2. 接続情報の取得

Supabase Dashboard → **Settings** → **API** で以下を控える：

| 項目 | 使用する環境変数 |
|---|---|
| Project URL | `SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_URL` |
| anon / public key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| service_role key | `SUPABASE_SERVICE_ROLE_KEY` |

### 1-3. DB スキーマ適用

ローカルから本番 Supabase にマイグレーション（62本）を一括適用する。

```bash
# ローカルの .env に本番Supabaseの接続情報を設定してから実行
npx supabase db push
```

> 実行前に `.env` の `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` が本番値になっていること。

## Step 2: .env の作成

```bash
cp .env.example .env
```

以下の項目を埋める（残りは Step 3〜4 で順次設定）：

```bash
# --- Supabase（Step 1 で取得）---
SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJ...
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...

# --- Web ---
REVALIDATE_SECRET=<任意の文字列を生成して設定>
CHAT_DAILY_COST_LIMIT_USD=1
```

> `REVALIDATE_SECRET` は `openssl rand -hex 32` 等で生成する。

## Step 3: Vercel プロジェクト作成

### 3-1. Web プロジェクト

1. https://vercel.com で「Add New Project」→ GitHub リポジトリ `mirai-gikai-fukuoka-city` を接続
2. 以下を設定：

   | 設定項目 | 値 |
   |---|---|
   | Framework Preset | Next.js |
   | Root Directory | `web` |
   | Install Command | `cd .. && pnpm install --frozen-lockfile` |
   | Build Command | `pnpm run build`（デフォルト） |

3. 環境変数に以下を設定：

   | 変数名 | 値 |
   |---|---|
   | `SUPABASE_URL` | 本番 Supabase URL |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
   | `NEXT_PUBLIC_SUPABASE_URL` | 本番 Supabase URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key |
   | `REVALIDATE_SECRET` | .env と同じ値 |
   | `AI_GATEWAY_API_KEY` | Step 4 で取得 |
   | `LANGFUSE_PUBLIC_KEY` | Step 4 で取得 |
   | `LANGFUSE_SECRET_KEY` | Step 4 で取得 |
   | `LANGFUSE_BASE_URL` | `https://cloud.langfuse.com` |
   | `ADMIN_URL` | Admin の Vercel URL（Step 3-2 完了後に設定） |
   | `CHAT_DAILY_COST_LIMIT_USD` | `1`（試験運用時） |

4. Spend Management: Dashboard → Settings → Billing → Spend Management で月の上限を設定（例: $30/月）

### 3-2. Admin プロジェクト

1. 「Add New Project」→ 同じリポジトリを接続（別プロジェクトとして）
2. 以下を設定：

   | 設定項目 | 値 |
   |---|---|
   | Framework Preset | Next.js |
   | Root Directory | `admin` |
   | Install Command | `cd .. && pnpm install --frozen-lockfile` |
   | Build Command | `pnpm run build`（デフォルト） |

3. 環境変数に以下を設定：

   | 変数名 | 値 |
   |---|---|
   | `SUPABASE_URL` | 本番 Supabase URL |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
   | `NEXT_PUBLIC_SUPABASE_URL` | 本番 Supabase URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key |
   | `NEXT_PUBLIC_WEB_URL` | Web の Vercel URL（Step 3-1 完了後に設定） |

4. **Admin のアクセス保護**: Dashboard → Settings → Deployment Protection → Password Protection を ON（Pro 機能）

### 3-3. Vercel AI Gateway 設定

1. Vercel Dashboard → AI → Gateway
2. 「Create Gateway」でゲートウェイ作成
3. Anthropic の API キーを登録
4. 発行された `AI_GATEWAY_API_KEY` を Web プロジェクトの環境変数に設定

## Step 5: Admin ユーザーの作成

シードデータには管理者ユーザーが含まれないため、Supabase Dashboard で手動作成する。

### 5-1. ユーザー作成

Supabase Dashboard → **Authentication** → **Users** → **「Add user」** → **「Create new user」**

- Email: 管理者のメールアドレス
- Password: 強力なパスワード

### 5-2. admin ロール付与

Supabase Dashboard → **SQL Editor** で以下を実行：

```sql
UPDATE auth.users
SET raw_app_meta_data = jsonb_build_object(
  'provider', 'email',
  'providers', ARRAY['email'],
  'roles', ARRAY['admin']
)
WHERE email = 'your-admin@example.com';
```

### 5-3. 確認

```sql
SELECT email, raw_app_meta_data FROM auth.users WHERE email = 'your-admin@example.com';
```

`raw_app_meta_data` に `"roles": ["admin"]` が含まれていれば OK。

# 福岡市議会データ取込設計書

作成日: 2026-03-29

---

## 1. 概要

福岡市議会の議案データをみらい議会ー福岡市版に取り込み、市民が議案内容をわかりやすく閲覧できるようにする。

公式サイトに掲載されている議案情報（番号・タイトル・審議結果・会派別採決）と、各議案のPDFをもとに、AIが生成したわかりやすい解説文をあわせて掲載する。

### 目指す状態

- 議案一覧・詳細ページに福岡市の実データが表示される
- 各議案に「やさしい解説」と「詳しい解説」が掲載される
- 会期・委員会・会派などのマスターデータが福岡市仕様になっている
- 新しい会期のデータを担当者が効率よく取り込める運用フローが整っている

## 3. データモデルと対応関係

### 3-1. council_sessions（会期）

| DBフィールド | 設定内容 | 例 |
|---|---|---|
| `name` | 会期名 | 令和8年 第1回定例会（2・3月） |
| `slug` | URL用識別子 | r8-1 |
| `start_date` | 開始日（西暦） | 2026-02-17 |
| `end_date` | 終了日（西暦） | 2026-03-27 |
| `council_url` | 公式ページURL | https://gikai.city.fukuoka.lg.jp/result/r8_gikai1/ |
| `is_active` | 現会期フラグ | true |

### 3-2. bills（議案）

| DBフィールド | 設定内容 | 例 |
|---|---|---|
| `bill_number` | 議案番号 | 第1号 |
| `name` | 議案タイトル（公式名称） | 令和７年度福岡市一般会計補正予算案（第６号） |
| `council_session_id` | 会期ID（外部キー） | - |
| `committee_id` | 委員会ID（外部キー） | - |
| `status` | 審議ステータス | approved / rejected / in_committee 等 |
| `publish_status` | 公開状態 | draft（初期）→ published（確認後） |
| `published_at` | 公開日時 | - |

#### status の対応表

| 議決結果（公式） | システムの status |
|---|---|
| 可決 | `approved` |
| 否決 | `rejected` |
| 継続審査 | `in_committee` |
| 審議中 | `in_committee` |
| 未議決 | `submitted` |

### 3-3. bill_contents（議案解説コンテンツ）

AIが生成する解説文を格納します。1議案につき2種類を作成します。

| difficulty_level | 用途 |
|---|---|
| `normal` | やさしい解説（市民向け。専門用語を使わず3〜5分で読める分量） |
| `hard` | 詳しい解説（政策的な背景・論点を含む詳細版） |

| DBフィールド | 内容 |
|---|---|
| `title` | わかりやすいタイトル（公式名称とは別に設定） |
| `summary` | 1〜2文の要約 |
| `content` | 本文（Markdown形式） |

### 3-4. factions（会派）

福岡市議会の会派をマスターデータとして登録します。

### 3-5. faction_stances（会派見解・採決結果）

公式サイトの会派別採決情報を格納します。

| DBフィールド | 内容 |
|---|---|
| `bill_id` | 議案ID |
| `faction_id` | 会派ID |
| `type` | `for`（賛成）/ `against`（反対） |
| `comment` | コメント（任意） |

## 5. AI要約生成の仕様

### 5-1. 入力

- 議案タイトル（公式名称）
- PDF抽出テキスト（全文）
- 議決結果・会派別採決データ

### 5-2. 出力（normal）

```markdown
## [わかりやすいタイトル]

**要約**: [1〜2文で議案の目的をまとめる]

### この議案は何をするものですか？
[市民が日常生活との関連で理解できる説明]

### 誰に影響がありますか？
[対象者・範囲]

### 審議の結果は？
[議決結果と会派別賛否の簡潔なまとめ]
```

### 5-3. 出力（hard）

```markdown
## [タイトル]

**要約**: [要約]

### 背景・目的
[政策的背景、改正理由など]

### 主な変更点・内容
[具体的な制度変更、予算額など]

### 審議経過
[委員会審査、主な論点]

### 採決結果
[会派別賛否の詳細]
```

### 5-4. 注意事項

- PDFがテキスト抽出困難な場合は、公式タイトルと議決情報のみでコンテンツを生成する
- 生成されたコンテンツはAdmin画面でレビュー・修正してから公開する
- 誤情報リスクを考慮し、必ず人間がチェックする運用とする

## 6. 実装フェーズ

### Phase 1: マスターデータ整備（手動）

手作業でDBに登録します。

- [ ] 会期（council_sessions）の登録
- [ ] 委員会（committees）の登録（福岡市議会の常任委員会・特別委員会）
- [ ] 会派（factions）の登録

### Phase 2: 議案データの取込スクリプト作成

`packages/seed/` 配下にスクリプトを作成します。

```
packages/seed/
└── fukuoka/
    ├── scrape-bills.ts        # 公式サイトから議案一覧を取得
    ├── extract-pdf.ts         # PDFからテキスト抽出
    ├── generate-content.ts    # AI要約生成
    └── import-bills.ts        # DBへの一括登録
```

#### scrape-bills.ts の処理内容

1. 会期URLのHTMLを取得
2. テーブル（`#tablepress-XXXX`）をパース
3. 以下を抽出：
   - 議案番号、タイトル、提出日、議決日、議決結果
   - 会派別採決（○/×）
   - PDFリンク
4. 令和表記を西暦に変換（例: `R8.2.17` → `2026-02-17`）

#### generate-content.ts の処理内容

1. PDF URLからテキストを抽出
2. Claude APIに送信してnormal/hard両形式の解説を生成
3. 生成結果をJSONまたはCSVで出力（レビュー用）

#### import-bills.ts の処理内容

1. レビュー済みの解説コンテンツと議案データをDBに一括登録
2. 冪等性を保つ（議案番号をキーにupsert）
3. 公開状態は `draft` で登録し、Admin画面から個別に公開する

### Phase 3: Admin画面でのレビュー・公開

既存の議案編集画面を使用します。

1. 取込後は `publish_status: draft` 状態
2. Admin画面で解説内容を確認・修正
3. 問題なければ `published` に変更して公開

## 7. 運用フロー（定期更新）

新しい会期が始まるたびに以下の手順を実施します。

```
1. council_sessions に新しい会期を追加
2. scrape-bills.ts を実行して議案一覧を取得
3. generate-content.ts を実行してAI解説を生成
4. 出力ファイルをレビュー・修正
5. import-bills.ts を実行してDBに登録
6. Admin画面で個別に公開状態を確認・切り替え
```

## 8. 考慮事項

### 公式サイトへの配慮

- スクレイピング時は適切なインターバル（1〜2秒）を設ける
- User-Agentを明示する
- PDFは1件ずつ順次ダウンロードする

### AI生成コンテンツの品質管理

- 生成された解説は必ず担当者がレビューする
- 金額・日付・固有名詞は原文と照合する
- 公開前チェックリストを設ける

### PDFのテキスト抽出について

福岡市議会のPDFはPDF 1.6（zip deflate）形式で、`pdftotext`（poppler-utils）によるテキスト抽出が可能。
ただし議案種別によって抽出品質に差がある。

| 議案種別 | PDFの特徴 | 抽出品質 |
|---|---|---|
| 条例改正案 | 「理由」セクション＋改正条文。テキスト中心 | 良好。AI要約に最適 |
| 補正予算案 | 冒頭条文は読めるが、予算額テーブルが断片化しやすい | 条文部分は良好、数値テーブルは補完が必要 |
| その他（人事案等） | 案件による | 要確認 |

- 抽出テキストはそのままAIに渡すのではなく、議案種別に応じて有効な部分（条文・理由・冒頭条文）を優先して入力する
- 予算案など数値が主体の議案は、テーブルの断片化を前提にAIプロンプトを設計する
- 抽出が著しく困難な場合は、公式タイトル・議決結果のみでコンテンツを生成し、手動補記を促す

## 9. 議案種別と取込優先度

福岡市議会の議案は種別ごとに取込・解説生成の優先度を設定する。

| 優先度 | 種別 | 例 | 解説生成の方針 |
|---|---|---|---|
| ★★★ 高 | 条例改正案 | 火入れ許可に関する条例の一部改正 | 「理由」セクションが明確。AI要約に最適 |
| ★★★ 高 | 補正予算案・予算案 | 一般会計補正予算案 | 市公式の予算概要ページへのリンクを議案ページから提供。概要ページの内容表示は別設計書で定義 |
| ★★☆ 中 | 専決処分の承認 | - | 背景・経緯の説明が重要。なぜ議会を経ずに処分されたかを含めて解説 |
| ★☆☆ 低 | 職員定数条例 | 職員定数条例の一部改正 | 対応するが優先度は低い |
| ★☆☆ 低 | 人事案件 | 教育委員会委員の選任 等 | 対応するが優先度は低い |

### 予算案の表示方針

予算案の議案ページでは、福岡市が公式に公開している**予算概要ページへのリンク**を提供する。

- 令和8年度当初予算案 → 市公式の当初予算概要ページ
- 令和7年度2月補正予算案 → 市公式の補正予算概要ページ

概要ページの内容をみらい議会上で表示する機能については、**別途設計書を作成する**。本設計書のスコープ外とする。

## 10. 継続審査案件の扱い

継続審査になった議案は、**最新の会期IDに更新する**方針とする。

- スキーマ変更不要（現状の1議案=1会期のまま対応）
- 継続審査が確定したタイミングで Admin 画面から `council_session_id` を更新する

## 11. スコープ外

- 委員会情報の紐付け（当面は本会議中心で運用。committee_idは未設定のまま）

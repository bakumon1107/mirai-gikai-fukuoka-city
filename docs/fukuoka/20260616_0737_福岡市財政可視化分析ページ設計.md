# 福岡市「税金の使い道」可視化・分析ページ 設計検討

作成: 2026-06-16 / 改訂: e-Stat一本化・福岡市分析へ転換 / ステータス: **方針確定（データ詳細の特定を残す）**

## 1. 目的・背景
**福岡市自体の財政を、市民にわかりやすく読み解く**可視化・分析ページを作る。他自治体との横比較は行わず（それは外部「税金の使い道マップ」の役割）、**福岡市の時系列の変化・収入/歳出構造・人口との関係**にフォーカスする。

- データ量は小さく更新頻度も低いため、**DBは使わない**（更新スクリプトでJSON同梱）。
- 既存の基本レイアウト（ヘッダ/フッター）は維持する。
- **市民にわかりやすく**を最優先。出典を明示する。

データ取得の技術詳細（統計コード・statsDataId・団体コード・手順）は **skill `fukuoka-finance-map`** に集約済み。

## 2. データソース：福岡市公式「地方財政状況資料集」Excel
**福岡市公式の「地方財政状況資料集（各年度決算）」Excel** を一次ソースとする。最新（令和6年度＝2024）・年度別・歳入財源別/歳出目的別/総額/人口/財政指標を含む。出典は「福岡市オープンデータ（地方財政状況資料集）」で統一。詳細は skill `fukuoka-finance-map` 参照。

- URL: `…/zaisei/zaisei/shisei/documents/{N}zaiseijoukyoushiryoushuu.xlsx`（N=令和の年）。令和2〜6（2020〜2024）の5年分を取得。
- 抽出（**読み違い防止**）: 「普通会計の状況」シートから歳出目的別・歳入財源別を**ラベルベース**で抽出し、**目的別合計＝歳出合計の突合で検証**（令和2〜6で1円まで一致を確認済み）。総額・人口・財政指標は「総括表」から。
- 取得スクリプト: `scripts/fetch-fukuoka-finance.py`（openpyxl）→ 千円単位のJSONを同梱。UI側で円換算。
- **不採用**: 福岡市オープンデータ旧CKAN（ドメイン廃止＝NXDOMAIN）／移行先BODIK（財政内訳なし）／e-Stat地方財政状況調査API（福岡市は2018止まり）／税金マップ（第三者・許諾不明）。
- 環境注意: 外部取得は `dangerouslyDisableSandbox: true`。同一Bash内完結 or worktree実パスへ直接書き出し。

## 3. 確定した方針（ユーザー合意済み）
- **D1 取得/反映**: 更新スクリプト（`scripts/fetch-fukuoka-finance.py`）でExcelを取得→整形JSONを同梱（DBなし）。
- **D2 グラフ**: ハイブリッド。時系列・2軸の推移グラフは **recharts** を導入（該当グラフのみ Client Component）。単年の構成比は CSSバー・アコーディオンで継続（軽量・Server Component）。
- **D3 データ源**: 福岡市公式「地方財政状況資料集」Excel（令和2〜6＝2020〜2024）。
- **D4 他自治体比較**: 行わない（外部サイトの役割）。
- **D5 分析の射程**: 5年（2020〜2024）の推移分析。
- **D6 出典**: 「福岡市オープンデータ（地方財政状況資料集）」に統一明記。

## 4. 分析の中核（優先順位：ユーザー指定の上位3つ）
1. **収入構造（自主財源の厚み）**: 地方税など自主財源 vs 国庫支出金・地方交付税・地方債など国・借入依存の割合と**その推移**。「福岡市が自分で稼ぐ力」と依存度の変化。
2. **歳出の重点（何に使うか）**: 民生費（福祉）・教育費・土木費などの構成と**推移**。福岡市が何を優先してきたか。
3. **人口との関係**: 人口推移・高齢化と、1人あたり歳出・民生費の関係。人口動態が財政に与える影響。
4. （補助）ふるさと納税：余力があれば。優先度は下げる。

## 5. ページ構成案（市民にわかりやすく）
1. **ヒーロー / サマリ**: 「福岡市のお金（最新年度）」歳入・歳出総額、1人あたり額、前年からの変化。
2. **お金はどこから来る？（収入構造）**: 自主財源／依存財源の構成比バー＋**経年推移**。地方税比率の推移を強調。
3. **何に使われる？（歳出の重点）**: 目的別構成比バー、アコーディオンで細目。主要費目の**経年推移**。
4. **人口と財政**: 人口推移グラフ、1人あたり歳出・民生費の推移。高齢化との関係を一言解説。
5. **読み解き（インサイト）**: 上記から見える福岡市の特徴・変化を平易な言葉で要約（市民向けの「つまり何が言えるか」）。
6. **出典・免責フッター**: e-Stat 出典、基準日・調査年度、加工の注記。

各セクションに**短い解説文**を添え、数字の意味を市民目線で言語化する（単なるグラフ羅列にしない）。

## 6. 想定ディレクトリ構成
```text
web/src/features/city-finance/
├── shared/types/            # 整形済み財政・人口JSONの型
├── shared/utils/            # 千円→億/兆 変換, 構成比, 1人あたり, 前年比（純粋関数＋テスト必須）
├── server/loaders/          # 同梱JSONの読み込み
├── server/components/       # サマリ/収入構造/歳出/人口 セクション(Server)
├── client/components/       # 推移グラフ(recharts/Client)
└── data/                    # fukuoka-finance.json（同梱・整形済み）
scripts/fetch-fukuoka-finance.py  # 福岡市資料集Excel 取得・整形・同梱（openpyxl）
web/src/app/(main)/finance/page.tsx  # 薄いラッパー（ヘッダ/フッターは(main)で自動維持）
```
- ルート: `/finance`（市の財政全体）。既存 `/budget`（議案単位の予算概要）とは役割が異なるため混同させない。

## 7. 出典・利用規約
- ページに **「出典: 福岡市オープンデータ（地方財政状況資料集）」** を明記。年度を併記。
- 「公開データを加工して作成。正確な内容は出典元の公式資料をご確認ください」の注記。
- 一次・公式ソースのため二次利用・再配布の懸念は小さい。福岡市オープンデータの利用条件に従う。

## 8. 概算タスク（実装フェーズ）
1. **データ特定**（appIdで）：最新年の歳出表ID・歳入表ID・住基人口表ID を確定。
2. **取得スクリプト** `scripts/fetch-fukuoka-finance.ts`：年度横断で取得→正規化→`data/` にJSON同梱。
3. **型・純粋関数＋テスト**：単位換算・構成比・1人あたり・前年比。
4. **loaders / セクションComponent**：サマリ→収入構造→歳出→人口→読み解き。
5. **推移グラフ（recharts・Client）・年度トグル**、構成比は CSSバー・アコーディオン。
6. **出典・免責、トップ導線**。
7. lint/typecheck/test → PR（base: fukuoka-city/develop）。

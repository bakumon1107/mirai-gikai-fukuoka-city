# 議案検索 絞り込みフィルタ（会期・カテゴリ・ステータス）設計

- 作成日: 2026-06-27
- ブランチ: `feat/bill-search-filters`（`docs/bill-search-design` からスタック）
- 親設計書: `docs/20260626_1500_議案検索機能設計.md`（`docs/bill-search-design` ブランチ）

## 1. 背景

親設計書 §10.3 のシグナル駆動バックログのうち「1検索あたりの結果件数が多い→絞り込みフィルタ」を、フィルタの種類が少ないというユーザーフィードバックを受けて先行実装した。

## 2. 仕様

### フィルタ3種（URLパラメータと1:1対応）

| フィルタ | パラメータ | 値 | 選択肢の取得元 |
| --- | --- | --- | --- |
| 国会会期 | `session` | `diet_sessions.id` | `findAllDietSessions()`（新規・開始日降順） |
| カテゴリ | `tag` | `tags.id` | `findFeaturedTags()`（既存流用） |
| ステータス | `status` | フィルタ値（下表） | `STATUS_FILTER_OPTIONS`（定数） |

### ステータスフィルタのマッピング

表示ラベルが議院に依存する `in_originating_house` / `in_receiving_house` は「審議中」に集約する。

| フィルタ値 | ラベル | 対象 status |
| --- | --- | --- |
| `deliberating` | 審議中 | `in_originating_house`, `in_receiving_house` |
| `enacted` | 成立 | `enacted` |
| `rejected` | 否決 | `rejected` |
| `introduced` | 提出済み | `introduced` |
| `preparing` | 準備中 | `preparing` |

`resolveStatusFilter()`（純粋関数・テスト付き）が URL 値→status 集合に解決し、未知の値（URL改ざん等）は null＝フィルタなしとして扱う。テストで「全 enum がいずれかの選択肢でカバーされている」ことを検証し、enum 追加時の漏れを検出する。

### 挙動

- **キーワードなしでもフィルタのみで検索可能**（「成立した議案一覧」のような絞り込み一覧として機能）
- キーワード変更時も選択中のフィルタは維持される
- フィルタ状態は URL に載るため共有可能
- 「絞り込みを解除」ボタンでフィルタのみリセット（キーワードは維持）

```
web/src/lib/routes.ts  # routes.search(q?, filters?) に拡張
```

### 設計上の判断

- **タグ絞り込みは2段クエリ**: `bills_tags` から対象 `bill_id` を先に解決してから `.in("id", ids)`。select 文字列の動的組み立てを避け、supabase-js の型推論を保つため。
- **Radix Select は空文字 value 不可**のため「指定なし」はセンチネル値 `"all"` で表現。
- `routes.search()` の第2引数に `typeof filters === "object"` ガードを入れ、routes.test.ts のダミー文字列引数呼び出しでも壊れないようにした。
